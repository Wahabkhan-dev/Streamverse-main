## Priority 1 — account, billing and access correctness

1. **Refresh-token rotation is not atomic.** `streamverse-api/src/services/auth.service.ts`, `repositories/authSession.repository.ts`: two requests can both read an unused token before either revokes it and both issue replacement sessions. Reproduced with concurrent calls. Claim the token conditionally inside a transaction and allow exactly one winner.
2. **Password reset can partially complete.** `services/auth.service.ts` updates the password, marks the token, and revokes sessions without one transaction. A revocation failure can leave a changed password despite an error response; token consumption also lacks an atomic claim. The partial-failure case is reproduced. Make credential change, reset-token consumption and session revocation atomic.
3. **Webhook crash recovery drops pending events.** `controllers/webhook.controller.ts` acknowledges every existing event except FAILED, including PENDING, despite the comment saying PENDING can retry. A crash after event insertion can permanently skip processing. The lookup/create sequence also races on duplicate delivery. Implement transactional event claiming, stale-claim recovery, and idempotent business operations.
4. **Subscription recovery/order handling is incomplete.** `services/billing/subscription.service.ts` treats UNPAID as terminal, blocking subsequent legitimate recovery. Other state updates lack an event-order guard. Reconcile against current provider state and distinguish recoverable versus truly terminal states.
5. **Duplicate provider subscriptions are not prevented durably.** Checkout creation has no database-backed pending-subscription reservation; embedded checkout uses a fresh idempotency key for each request. Handling an extra subscription without reconciling/cancelling it can leave external billing active. Verify retries, parallel requests, and old/new subscription event order against Stripe test mode before release.
6. **Changing a plan's Stripe price can break existing subscription mapping.** The billing service resolves plans through the current `stripePriceId`. Keep historical price-to-plan mappings or persist the association independently.
7. **Externally initiated refunds can be ignored.** `services/billing/refund.service.ts` relies on a known local Stripe refund ID rather than reconciling an unknown refund back to its payment. Reproduced. Stripe-dashboard refunds must update local payment/refund state too.
8. **Asynchronous refund settlement is incomplete.** `services/billing/stripeWebhook.service.ts` handles `charge.refunded` but lacks a complete `refund.updated` / `refund.failed` reconciliation path. Pending or failed refunds can retain misleading local status/notifications. Also reconcile uncertain network outcomes before issuing a new refund request; reserve remaining refundable balance atomically for concurrent requests.
9. **Revenue totals can become negative after a full refund.** `repositories/analytics.repository.ts` counts only SUCCEEDED payments as gross, excludes fully refunded charges, then subtracts their refunds. A fully refunded 1,000-unit payment produces -1,000 instead of zero. Reproduced. Separate charge gross, refunds and net. Do not sum different currencies as interchangeable cents.
10. **Expired age verification still grants access.** `services/entitlement/entitlement.service.ts` does not enforce the verification's `expiresAt` in the access check. Reproduced. Define and enforce expiry consistently.
11. **Plan video-quality limits are not enforced in media delivery.** `maxVideoQuality` is stored/validated but delivery does not filter or authorize HLS renditions by that limit. Enforce the limit in playlists and rendition access, rather than only in UI metadata.
12. **Device limits can be bypassed by omitting device registration.** Playback-session creation does not require a validated, owned device ID; the client registration path is optional from the API's perspective. Require the device binding where plan quotas apply. Also recheck stream admission after a paused session expires: continued media access and heartbeat updates alone do not establish a renewed stream slot.
13. **Entitlement cache can serve obsolete access.** `services/entitlement/entitlementCache.service.ts`: content invalidation has no callers; country/content changes are not comprehensively invalidated, and TTL is not clamped to availability deadlines. Expired distinct keys are retained until revisited, permitting memory growth. Add invalidation at mutations, expiry-aware TTL, and bounded eviction.
14. **Signed delivery URLs remain usable after account/entitlement changes.** HLS/offline delivery verifies token signature/content scope without rechecking the subject's current account/subscription. Default URL validity is measured in hours. This is a revocation-policy/security gap, not an unsigned public-file bypass. Decide the permitted revocation delay; shorten or revalidate tokens accordingly. Previously issued segment URLs remain valid independently.

## Priority 2 — customer and admin functionality

15. **Profile form values disagree with the backend schema.** `streamverse/src/routes/_site.profile.tsx` sends country labels and quality strings such as `United Kingdom` / `1080p`; the backend accepts country codes and quality enums such as `GB` / `HD`. Schema rejection reproduced. Some displayed fields are local-only; optimistic success/local state can survive a failed save. Use one DTO mapping and display success after persistence.
16. **Admin legal changes do not persist to the real backend.** `routes/admin.legal.tsx` saves/publishes local store state. The API update wrapper's method/path also disagrees with draft/publish routes. Initial editor state is not synchronized when the asynchronous query completes. Implement the draft/publish flow end to end and refresh from the returned document.
17. **Admin announcements can say sent without sending.** `routes/admin.notifications.tsx` updates local announcements rather than the available backend announcement endpoint in live mode. Connect mutation/status/error handling to the API.
18. **Creating a subscription plan omits required fields.** `routes/admin.subscriptions.tsx` sends name, amount, interval, features and active, but no required slug or Stripe price identifier. Existing-plan partial updates do not prove creation works. Supply and validate the full create DTO.
19. **Admin payment display misrepresents backend data.** `routes/admin.payments.tsx` uses incompatible status/flat-field mappings and monetary-unit assumptions; page-local totals do not represent all payments. Map nested DTOs explicitly, format minor units/currency correctly, use the backend summary, and implement pagination-aware filters.
20. **Audiobook chapter playback uses the wrong timeline.** In the audiobook player, cumulative book offsets are applied to individual chapter files; local chapter time/duration is treated as book progress, and ending one file does not reliably advance to the next chapter. Model chapter index plus local time, then derive whole-book progress.
21. **Audio failure can switch live playback into simulated progress.** The audio error path disables real audio and permits the timer-based demo behavior. A customer can see progress with no working audio. Restrict simulation to explicit demo mode and show a recoverable error in live mode.
22. **Long-lived audio/ebook sessions can outlive their signed URLs.** URLs are obtained once with short default expiry; later seeks/range requests may fail without renewal. This needs a live long-session/range-request test. Refresh authorization before expiry or on the appropriate failure.
23. **Some access UI still uses mirrored local state.** `PlayerGate` / `useGate` can disagree with current server subscription, country or age status. The backend remains the authority; consolidate live-mode decisions around its returned entitlement state to avoid false blocks and stale prompts.
24. **Legal API failures can silently show seeded policies.** The public legal page falls back to static/demo text, potentially including unresolved placeholders. Distinguish unavailable legal content from an intentionally published policy; show a retry/error state in live mode.

## Priority 2 — storage and background processing

25. **Cleanup loses records when storage deletion fails.** `services/media/mediaCleanup.service.ts` catches the object-deletion error and still hard-deletes the database row. Reproduced. The upload-abort path has a similar risk. Preserve retry metadata and only finalize after verified deletion.
26. **Derived media and multipart parts can be orphaned.** Deleting the original asset/rows does not comprehensively delete generated HLS objects or abort abandoned multipart uploads. Track all object prefixes/upload IDs and make cleanup retryable/idempotent.
27. **Processing failures are swallowed, defeating queue retries.** Video/audio workers set FAILED but resolve rather than rejecting. The video case is reproduced. BullMQ sees completion, so configured attempts do not retry. A process crash leaving PROCESSING also needs lease/stale-job recovery.
28. **Legacy movie paths can overwrite HLS output.** HLS root derivation still collides for different legacy master paths belonging to the same content. Reproduced. The newer library master paths are isolated; do not generalize this defect to all uploads. Include an immutable source/version identifier in every derived prefix.
29. **Transcoding can exhaust memory or run indefinitely.** Generated segments are read into memory in parallel; processing large media needs streaming/bounded concurrency, explicit process limits/timeouts, and load testing. This is a capacity risk, not a measured production outage.
30. **Revoked device registration does not reactivate or clearly reject.** The upsert update omits status, returning REVOKED for the registration path. Reproduced. Define reactivation policy and return an actionable response.
31. **Settings batches partially apply before validation fails.** Valid entries are saved before a later invalid entry throws. Reproduced. Validate the entire batch first, then commit transactionally.

## Security findings and configuration risks

32. **Known vulnerable dependencies require updates and regression tests.** Frontend affected nodes: `vite`, `launch-editor`, `@xmldom/xmldom`, `epubjs`, `zod`, `vitest`, `@vitest/mocker`. Backend: `body-parser`, `zod`, `deepmerge-ts`, `@prisma/config`, `prisma`, `ip-address`. Development-tool findings and production-reachable parsers have different exposure. Do not run a forced major dependency upgrade blindly. Audit results are a dated advisory snapshot, not proof of exploitability. Primary references: [body-parser compressed-request DoS](https://github.com/advisories/GHSA-27r3-jxmh-p828), [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [Vite advisory](https://github.com/advisories/GHSA-9jrq-w75r-8gcw). Exact dependency paths/advisories are in the audit JSON files.
33. **Spreadsheet formula injection in CSV exports.** `streamverse/src/lib/csv.ts` escapes CSV delimiters but preserves leading formulas in user-controlled names/fields. Reproduced with `=1+1`. Export spreadsheet-safe text according to the intended consumer; CSV quoting alone is insufficient. See [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection).
34. **Account-specific login/recovery throttles use unnormalized email.** Case/whitespace variants generate different limiter keys while referring to the same normalized account. Reproduced for login keys. General IP throttling still exists. Normalize consistently and consider an account-level throttle across source IPs.
35. **Country restrictions depend on self-declared profile country.** A signed-in customer can change that field. If territorial licensing requires trusted location, this is inadequate evidence; choose and document the policy, using appropriately trusted signals where required.
36. **Malware scanning is optional/fail-open when unconfigured.** `services/media/malwareScan.service.ts` accepts uploads with a NOT_CONFIGURED result. Admin-only upload access reduces exposure but is not a scan. Define required production scanning and isolate untrusted document processing.
37. **Rich HTML sanitization has trust-boundary gaps to review.** `lib/legal.ts` returns raw HTML when no browser window exists, and the rich-text editor initially assigns supplied HTML to `innerHTML` before change-time sanitation. Sanitize on ingestion and rendering. A full stored-XSS exploit was not established in this review; do not call this a proven public SSR exploit.
38. **Development infrastructure must not be exposed as production.** Vite permits all hosts; Compose publishes database/Redis ports with development authentication assumptions. Restrict binding and credentials for any remotely reachable environment. No public exposure was proven.

Positive controls observed: Stripe webhook signature verification uses the raw body; backend authorization exists for admin routes; account status/role is re-read for authenticated requests; refresh tokens are hashed; media tokens are signed/scoped; production environment guards exist. These observations do not constitute a penetration-test certification. No hardcoded private key was found by the targeted source scan; Git history and external secret stores were not exhaustively audited.

## Tooling, deployment and improvements

- `db:up` names `postgres`, while Compose uses the MySQL `db` service: the convenience command is broken. Align service names and document the current database.
- Compose/API frontend defaults disagree on API ports, and configured billing success/cancel paths need alignment with real frontend routes. Test a clean checkout using only documented commands.
- Tracked frontend defaults select demo mode; local overrides can select a localhost API. Make deployment mode/API origin explicit and validate a clean production environment. A successful build alone does not establish a real deployed API connection.
- Default Playwright discovery includes the live spec directory without the dedicated live configuration/setup. Separate smoke/demo/live suites explicitly. Keep a normal-browser-security live project mandatory for CORS verification.
- The checked-in Deno workflow does not validate these Node/Vite/Express packages. Add CI for both typechecks/builds/test suites, migrations and dependency checks; include targeted contract tests for the failures above.
- Formatting-disabled ESLint still reports 20 errors/82 warnings. Seventeen hook-rule diagnostics include naming/convention false positives (`eBookDetail`, route functions named `component`, a local function literally named `use`), not seventeen demonstrated hook-order crashes. Rename/wrap appropriately. Remaining errors include irregular whitespace, a control-character regex, and an unused expression. Warnings include 28 hook dependency and 53 React-refresh diagnostics; review behavior-sensitive dependencies rather than blanket suppression. One configuration warning is also present. The formatting-enabled run is separate and must not be inferred from historical lint counts.
- Add integration tests against disposable MySQL, Stripe test-mode lifecycle/replay scenarios, storage-failure injection, and long media playback. Add transactional operations/outbox reconciliation where external provider and database state can diverge.
- Large-file memory/timeout limits, cache eviction, upload cleanup observability, queue stale-job recovery, currency-correct reporting and accurate frontend error states are higher-value improvements than cosmetic formatting cleanup.

## Recommended order

First address atomic auth/token operations, webhook recovery, subscription/refund reconciliation, access-limit enforcement and vulnerable production dependencies. Next fix live admin/profile/player behavior and reliable media cleanup/retries. Then complete normal-browser/live integration coverage, deployment/CI alignment, and reviewed dead-code/formatting cleanup. Re-run verification after fixes; this report is a snapshot of a changing working tree, not a permanent warranty.
